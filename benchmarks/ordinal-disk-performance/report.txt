Disk reads and memory scope
---------------------------
The RDS reader retains paths, file sizes, and scalar counters only.
Input generation runs separately. Dense controls preallocate their full
inputs in the fitting process; source fits retain no x/y fields and
process blocks no larger than their declared size. Structural source
checks passed: TRUE.

These are median peak process RSS values, including R/package startup,
input storage, temporary fitting allocations, and the returned model.
They are not isolated native-allocation measurements. Callback elapsed
time measures readRDS/deserialization using R's elapsed clock. Logical
requested bytes, process CPU times, faults and OS I/O counters remain in
measurements.csv; OS-reported input operation range: 0 to 0 .
Generation, hash verification, and repeated reads warm the OS cache.
No cache was flushed. Logical bytes are not physical device traffic;
zero OS I/O counters do not establish that data never came from files.

Bounded reader/design retention does not establish constant or lower peak
process RSS. Repeated block reads and validation allocate temporary R
objects; garbage collection and allocator behavior can affect the process
peak. This panel measures that total without attributing its components.

Retained operational failure
----------------------------
The initial disk-v1 worker saved a successful fit, but the restricted
macOS resource collector could not query sysctl kern.clockrate and returned
exit 1. That incomplete attempt remains intact and is excluded from these
summaries. The same fixed panel was restarted in disk-v2 with permission
for the resource query; the worker, candidate, inputs, and settings did not
change. The result parser recognizes the macOS resource labels and rejects
missing resource records.

Retained build-provenance failure
--------------------------------
The complete disk-v2 retry loaded identical baseline and candidate native
binaries despite distinct installed headers: the package build had reused
objects after a header-only edit. Its records and invalid report remain
available but cannot measure the candidate. The two affected translation
units were then rebuilt. The runner now rejects identical binaries before
timing, and the result analysis verifies distinct hashes in every pair.
The separately compiled component panel used the intended headers.

Decision limits
---------------
The unchanged common-path control ratios range from 0.9403 to 1.0170.
That variation reinforces why small individual source-fit differences
should not be attributed to the patch. Across the full partial panel,
the larger and consistent dense-fit reductions support the row-work
optimization; source gains are smaller and more sensitive to other costs.
This candidate reduces row work, not the number of source reads. Whole-fit
effects must be read alongside component timings and callback costs. The
component wrapper is a separate translation unit, so its operation ratios
do not by themselves establish an installed whole-fit speedup. The
unchanged common path is a process-noise control. Sparse boundary behavior
is addressed by separate diagnostics and regression tests, not inferred
from these positive grouped-count timing fixtures.
A subsequent source-performance investigation should profile validation,
standardization, block conversion, and allocation alongside readRDS. The
present panel does not separate those costs, justify weaker source checks,
or demonstrate a reduction in peak memory from this arithmetic change.
