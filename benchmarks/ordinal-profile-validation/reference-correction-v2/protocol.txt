Ordinal analytic inference: implementation confirmation v1
===========================================================

This protocol is frozen before executing run.R on the six generated data
sets below. The earlier unit tests are development checks. This panel tests
implementation agreement; it is not a simulation of type-I error, coverage,
or a calibration exercise. No inferential constants are selected from its
outcomes. All failures remain in the result table.

Inputs and comparisons
----------------------
For each logit, probit, and cloglog link, use two independently seeded designs:
24 grouped rows, three categories and two predictors; and 60 grouped rows,
five categories and four predictors. Seeds are 113601 through 113606, assigned
in the order recorded in run.R. Each grouped row contains 20 observations
generated from a correctly specified cumulative-link model, with zero/one/two
integer row weights and a known nonconstant offset. These modest inputs test
numerical calculations with different parameter dimensions and nuisance fits.

For each case, compare the full likelihood and a constrained likelihood
(first slope = 0.15) against ordinal::clm on frequency-weighted category rows.
The reference constraint is represented by a known offset and a removed slope.
Compare the 95% profile limits for the first slope against ordinal's profile
construction. The software uses different numerical profile algorithms;
allow 5e-4 absolute difference in profile endpoints and 2e-6 absolute difference
in log likelihoods. These are numerical agreement thresholds, not scientific
equivalence margins. Endpoint target errors must be below 1e-5 and each
reported nuisance score and remaining predictor step below 1e-7.

Evaluate ordinary and full-model adjusted-score tests of a two-row linear
hypothesis: the difference between the first two thresholds is 0.8, and the
first slope minus 0.4 times the second is 0.15. Confirm the constraint residual
is below 1e-10 and the projected nuisance score below 1e-7. Re-express the two
constraints through an invertible row transformation and verify the statistic
agrees to 1e-7 absolute error. This checks hypothesis representation, not
finite-sample calibration. Numerical agreement in the score test does not
establish its asymptotic assumptions.

The MASS housing data supply an additional external comparison of ML profile
limits for InflHigh and ContHigh, for all three links, with the same endpoint
tolerance. These public data have already been used during development and
therefore are explicitly a reference regression check, not fresh confirmation.

Execution and provenance
-------------------------
Run from the repository root, after the shared native library has been built:

  Rscript benchmarks/ordinal-profile-validation/run.R OUTPUT_DIRECTORY

run.R loads the current package source with pkgload::load_all(compile=FALSE),
so a compiled src/fastglm.so from that source is required. It also requires
ordinal and MASS. This script is a developer validation tool, not a runtime
package dependency. OUTPUT_DIRECTORY must not exist. The runner saves the
complete generated inputs, every success/failure record, endpoint comparisons,
score checks, session information, and hashes of the sources/protocol/binary.
An existing output directory is never overwritten. Repeated execution should
agree numerically at the stated tolerances; platform floating-point results
and external profile interpolation need not be bit-identical.

No timing claim is drawn from this panel. Interpret every failure before
claiming success; repairing a defect requires a separate output namespace
and an explanation of whether the same data are being reused for regression
testing. The full-model adjusted-score nuisance convention and its first-order
derivation are in methods.txt.
